Fusion Data Structures

A reference card: the ways of keeping many values, which Fusion has today, which are coming, and how other languages offer them. Updated 2026-11-27 - for developers, and for the AIs that help build Fusion.

1. What this sheet explains

A data structure is a way of keeping many values so they are quick to use for a given job: in order, by key, first in first out, by position in space ... Each costs memory and time in different ways; picking the right one matters more than any later tuning.

Section 2 lists every structure in one table; section 3 gives each one a card - what it is, how Fusion writes it, how other languages offer it. The columns:

Status
built works today · planned scheduled in files/FEATURES.md · to study considered in 43.5 (which collections fusionlib offers) · FSMA a Data Stack kind proposed in research R11 · not planned left to a library
Order
whether the values keep the order they were added in (or a sorted order)
Access
how a value is reached: by position, by key, only the ends, by walking
Find / add
the usual cost of finding a value and of adding one: O(1) constant, O(log n) grows slowly, O(n) grows with the count
Same value twice
whether a value (or key) may appear more than once

Sources: Fusion's own design (Decisions.md COL.*, files/Arrays.md); ChatGPT's guide (files/Research/Memory/FSMA/DataStructures/) - a review with a limited view; the FSMA picture: files/Fusion Structured Memory Architecture.md.

3. Each structure

Fundamental

top

Array built

A fixed number of values side by side; reached by position, bounds always checked (COL.001).

int[5] scores = [90, 85, 77, 64, 50]
print("{@1}", scores[0])

C, Java, C# arrays; Rust [T; N]; Go [5]int. Fusion: files/Arrays.md.

top

Growable array built

An array that grows with add; still an array (bounds checked, one type).

int:[] seen
seen.add(4)

C++ vector, Java ArrayList, Rust Vec, Go slices.

top

Arrays of 2-3 dimensions, jagged built

Rows x columns (x depth), stored flat; a jagged array has rows of different lengths. Views reach a row or column.

int[2][3] grid
grid[1][2] = 5
int[][] jagged = [[1], [2, 3]]

C# int[,] and int[][]; NumPy arrays. Task 45.12.

top

List built

The everyday collection: grows, keeps order, never null - just empty (COL.003). Options: noDuplicates, noNull, readOnly. A class of your own may be a List (D.174).

List<string> names = ["Ada", "Bo"]
names.add("Cy")
names.sort()

Java List, C# List<T>, Python list.

top

Map (hash table) built

Values found by a key; its keys come out in the order they were added. Also written Dictionary.

Map<string, int> stock
stock["apples"] = 3

Java HashMap, C# Dictionary, Python dict, Go map. Map literals {"apples": 3} planned (L6.4).

top

Set planned

Each value once; quick to ask "is it there?". Today a List with noDuplicates does the job, slower.

Set<string> tags        // planned - L6.5, COL.014

Java HashSet, C# HashSet, Python set.

top

Tuple planned

A few values without declaring a struct. Underneath a struct made by the compiler: const, no field names, read by position, its values of mixed types (L6.7).

(string, int) pair = ("Ada", 36)     // planned
print("{@1}", pair[0])

Python, C#, Swift, Rust tuples.

top

Struct, enum built

A struct bundles values into one value type; an enum's values are built-in value structs with fields (D.188). files/Value_Structs.md.

struct Point
    int x
    int y
print("{@1}", EARTH.mass)

C / C# / Go / Rust structs; Java enums.

top

Stack (last in, first out) built

Add on top, take from the top. A List does it: add and removeLast (quick typing pop).

List<int> undo
undo.add(1)
int last = undo.removeLast()

Java Deque / Stack, C# Stack<T>, Python list.

top

Queue (first in, first out) to study

Add at the back, take from the front. A List works but taking from the front moves every value; a real queue (or the planned RingBuffer) doesn't. Which to offer: 43.5.

Java ArrayDeque, C# Queue<T>, Python collections.deque.

top

Linked list to study

Each value points to the next; cheap to insert in the middle, slow to reach by position, poor for the cache - rarely the best choice today.

Java LinkedList, C# LinkedList<T>.

Trees and graphs

top

Search trees to study

Keys kept sorted (a binary search tree, balanced as AVL or red-black) - a sorted map or set, walked in order, with ranges.

Java TreeMap, C# SortedDictionary, C++ std::map, Rust BTreeMap.

top

B-tree, B+ tree not planned

Wide trees built for disks - databases and file systems. A library's job.

top

Trie (prefix tree) to study

Text stored letter by letter, shared prefixes once: autocomplete, dictionaries, matching keywords.

top

Heap, priority queue to study

The smallest (or largest) value always on top; schedulers, timers, shortest paths.

Java PriorityQueue, C# PriorityQueue, Python heapq.

top

Graph, DAG to study

Nodes and the links between them - an adjacency list (Map<K, List<K>> today) or a matrix. A DAG has no loops: build orders, a service's dependencies.

Advanced, concurrent

top

Deque to study

Add and take at both ends in constant time.

top

Ring buffer planned

A fixed number of slots used round and round, the newest replacing the oldest - the first of the Collections module (43.4), and the input of a hot-path service (42.24).

top

Bitset to study

One bit per value: flags and compact sets of small numbers. bytes holds the bits today.

top

Others not planned

Bloom filter (a fast "maybe there"), LRU cache, skip list, union-find, segment and Fenwick trees, R- and KD-trees (space), rope (huge text), sparse array - each for one job; a library when a program needs it.

top

Between threads planned

Thread-safe and lock-free queues (one or many producers and consumers), concurrent maps, RCU. In Fusion a resource becomes a service with a mailbox, so programs rarely need these by hand (files/Concurrency.md, Task 42).

Fusion's own: Data Stacks

top

Data Stack FSMA

Not a collection to fill by hand but where objects live: a stack in the heap with a purpose (one frame, one type, a grid that reuses holes, the catch-all), made and released as a unit by the compiler - or by a developer:

DataStack<Customer> customers {
    layout: contiguous
    allocation: dynamic
    growth: automatic
    reclamation: automatic
}

Research only. files/Fusion Structured Memory Architecture.md sections 4 and 6.

top

New Data Stack kinds FSMA

Temporal (expiry), Versioned (history), Shared (several services), Stream (several readers), Indexed (find by a field), Transactional (all or nothing), Spatial (by position), Compressed (less memory). Best seen as capabilities of one Data Stack rather than separate designs.

files/Fusion Structured Memory Architecture.md section 7; research R11.9.
