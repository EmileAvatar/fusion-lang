Services designed - Task 42

Shared state without locks: a resource becomes a service, instead of every caller guarding it by hand.

The problem

Race conditions - two threads read a balance of 1000 at once, both withdraw 800, and both succeed. Locks - every caller must remember to lock and unlock; forget once and the race is back. Deadlocks - two threads each hold what the other waits for, and the program freezes.

What a service is

The service owns the data and is its only writer; threads send it requests instead of touching the data. Each request is one indivisible step, and the compiler decides how it runs.

Using a service

Example (designed - not built yet)
class Account
    int balance = 1000

void function withdraw(Account account, int amount)
    // The check and the change are one step: no other thread can
    // slip in between them, so two withdrawals can't both pass.
    service(account).run
        if account.balance >= amount
            account.balance -= amount

void function main()
    service Account account = Account()   // shared state: one owner, one writer
    go withdraw(account, 800)             // two threads withdraw at the same time
    go withdraw(account, 800)
    print(account.balance)                // 200, never -600

Why it solves them

No race conditions - only the service changes its data, one request at a time. No hand-written locks. No deadlocks by design - a caller never holds a lock while waiting. No cost when not needed - a service used by one thread is a plain variable.
