Fusion Programming Language - EBNF Grammar No version number until the compiler hosts itself (FEATURES 35.7). Synced with the Python compiler 2026-11-25: src/lexer/ (tokens, keywords.py), src/parser/parser.py, files/SYNTAX_REFERENCE.md and Decisions.md. The "ebnf" check in check.py fails when a keyword or reserved word of the lexer is missing here. Every rule above the PLANNED part is BUILT - the parser reads it. Rules for what is designed but not built are in the PLANNED part at the end, each with its task; the lexer may already read their tokens. NOTE: the ";" ending each rule is EBNF notation. Fusion itself has no semicolons - a statement ends at the end of its line.

44.3 built
Three block styles, mixed freely (SYN.001): 1. indentation (Python): INDENT ... DEDENT 2. braces (C): { ... } 3. End (VB.NET): the block, then "End" and its word - End if, End for, End function "End" may follow an indented or braced block as well; "end" is a keyword too (SYN.041). Inside ( ) and [ ] a line break only continues the line - no NEWLINE, INDENT or DEDENT there (Task 44.3), so an expression may span lines.
